# Проверки серверного прототипа — 24 октября 2026

Фактически развёрнута одна площадка: 185.174.166.93, Санкт-Петербург, 4 vCPU / 8 ГБ RAM. Это отдельный Compose project mosprom-prototype с обычным PostgreSQL, не Patroni и не распределённый production-кластер.

Проверено на реальном сервере:

- HTTPS с проверяемым сертификатом Let's Encrypt: `/` и `/app` возвращают 200; `/landing` перенаправляет на `/`. Медиа находятся в web-образе, видео Range возвращает 206.
- `/ready`: БД, миграции 0014, Redis, sim, production-конфигурация — ok. MEDIA_URL пропущен намеренно: статические файлы обслуживает web, существующий SeaweedFS не подключён.
- DEV_AUTH=0, X-Dev-User отвергается (401 при корректной ревизии); внутренние API снаружи закрыты (404). Неверная/отсутствующая ревизия блокируется отдельно (426). `/routing/ping` возвращает spb / prototype-20261024 и Cache-Control no-store.
- Полный браузерный сценарий на публичном адресе: лендинг, переходы, внешняя страница `/app` со ссылкой на бота, подтверждение 18+, intro, реальные команды и сохранение после reload. Telegram initData в этом сценарии подписан тестовым скриптом; это моделирование браузерного окружения Telegram, а не проверка реального Telegram WebView. Ошибок JavaScript нет.
- Настоящий Bot API через существующий Xray: getMe = cvnprombot; default menu button = https://ochakovo.velikoss.ru/app; webhook отсутствует; polling идёт, конфликтов 409 нет. Существующий Xray не перенастраивался. Во время диагностики дополнительный Python-процесс внутри контейнера вызвал один рестарт по памяти; дальнейшие проверки вынесены в отдельный временный контейнер. Бот стабильно занимает около 180 МиБ из 320 МиБ.
- Тестовая заявка создана через публичный API (201) и отозвана (204). HR `/hr` использует явный presentation mode с вымышленными кандидатами, код 123456; реальные заявки в этой демо-CRM не отображаются.
- Созданы 40 синтетических игроков рейтинга. Первая автоматическая резервная копия создана; расписание — раз в шесть часов, хранение семь суток. Дополнительный согласованный pg_dump восстановлен в отдельную временную БД; отдельная API прошла readiness и аутентифицированный bootstrap. Рабочая БД не заменялась. Временные API и БД удалены после проверки. После --no-acl явно восстановлены права роли приложения.
- PID и время запуска Patroni (1162442), etcd (240597) и существующего Xray (782120) совпадают с исходным снимком. Patroni остаётся running / replica, timeline 32. Существующий Caddy получил только новый site block; его исходный конфиг сохранён. Для Caddy 2.9.1 с admin off выполнен короткий перезапуск; прежний сайт после этого возвращает тот же HTTP 404 на `/`, что до изменения. Конфигурации и тома прочих проектов не менялись.

Проверки исходников: ESLint и svelte-check без ошибок/предупреждений; production-сборка; 54 теста HTTP/resolver/landing; Playwright smoke (четыре маршрута); 41 тест бота; 20 тестов deploy; ShellCheck и проверка Dockerfile. Все новые коммиты имеют автора и коммитера Denis Shipilov <shipiloff.d@gmail.com>.

Trivy 0.76.1, база от 24 октября 2026, AMD64, без ignore-unfixed: API, bot, web/Caddy, sim, Redis и исправленный PostgreSQL — **0 High / 0 Critical**. У первоначального PostgreSQL Debian были High-уязвимости; выбран Alpine и удалён ненужный Go-бинарник gosu, поскольку контейнер запускается сразу от postgres. Уязвимые варианты на сервере не запускались.

В этом запуске не выполнялись нагрузочное сравнение масштабирования, аварии площадок, переключение Patroni и сетевые разделения. Четыре датацентра остаются референсной схемой. Прототип доставлен проверенными архивами по SSH; подписанный GHCR/CD-релиз, provenance и многоузловая отказоустойчивость не заявляются. Автоматические бэкапы пока находятся на этом же хосте; проверочная копия дополнительно сохранена на компьютере оператора.
